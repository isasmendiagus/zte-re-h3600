# The egress contradiction is UNIVERSAL across all SW TX paths (2026-05-28 late)

## Established beyond doubt
- Stock CPU→LAN egress uses NO DMA ring: UP (0x10054/58/5c), DN (0x10064/68/6c), IDM
  (0x8040/44) ALL genuinely 0 during egress. The DN re-measure used the corrected method
  + double-read (proved live counters increment in-window while DN stayed stable 0). Not
  a measurement artifact. (`stock_dn_ring_REMEASURE_re.md`)
- Egress netdevs that tick: `sw`, `eth3`, `br0` (br0=192.168.1.1). (`stock_egress_netdev_id_re.md`)

## Every decomp SW TX path funnels to a ring kick (I read these myself)
- `pon_tm_net_tx` (plat:6721): dir-0 → raw_send(...,0)→kick 0x10054; dir-1 → raw_send(...,1)
  →kick 0x10064. (plat:6810, 6866, 6239/6242)
- `pon_tm_data_raw_send` (plat:6596): BMU alloc + memcpy + desc + `soft_insert_tx_1desc`
  → ring kick. (plat:6680)
- `pdt_ethdrv_send` (switch:789): ffe_learn + queue-select + `dev_queue_xmit_sk` bounce
  to _LC0/_LC1 ("sw"/"pon"). (switch:926)
- `swport_dev_xmit_fin` (switch:447): re-points skb->dev via dev_get_by_name(_LC0/_LC1)
  + `dev_queue_xmit_sk` bounce. (switch:497)

So pdt_ethdrv_send and swport_dev_xmit_fin BOUNCE → land on "sw"/"pon" → pon_tm_net_tx →
ring kick. There is NO ring-less SW TX path visible in the decomp.

## The contradiction
Decomp: 100% of SW TX → ring kick. Hardware: egresses with ZERO ring kicks. So stock's
real CPU→LAN egress does NOT execute the decomp's obvious SW TX path. Two leading
hypotheses for the ring-less egress:
1. **HW fast-forward engine (ffe)**: `ffe_learn_skb` is called in the TX path; a learned
   flow may be forwarded by HW without re-entering the CPU ring TX. (Caveat: the ICMP
   reply is LOCALLY generated by the CPU IP stack — HW fast-forward normally accelerates
   RX→TX forwarded flows, not locally-generated TX. So this hypothesis has a hole.)
2. **Memory-queue inject (not a register doorbell)**: the CPU may write the frame +
   descriptor into a DRAM queue/FIFO that the fabric polls, with no MMIO ring kick — which
   is why no ring counter moves AND a register-read diff wouldn't catch it.

## What this means for mainline
Mainline's UP-ring zx_sw_xmit reaches QMG sw_fwd but dies at SOPC. Stock doesn't use that
ring at all. Replicating any ring path is the wrong target (proven). The real egress is
ring-less and not visible in the static SW-TX decomp.
